Tópico 2.3.8

Troca de Mensagens (Message Passing)

Mecanismo de comunicação onde os processos trocam informações através de primitivas explícitas de send() e receive(), sem compartilhar o mesmo espaço de memória. O gerenciamento das filas pode ser síncrono (bloqueante) ou assíncrono (não-bloqueante).

Conceitos Fundamentais

  • Endereçamento Direto vs Indireto: No direto, os processos nomeiam o destino (`send(P, msg)`). No indireto, mensagens são enviadas para caixas de correio / filas (`send(mailbox, msg)`).
  • Bloqueante (Síncrono): O emissor é suspenso até que a mensagem seja recebida (*Rendezvous*), garantindo confirmação explícita de entrega.
  • Não-Bloqueante (Assíncrono): O emissor envia a mensagem para um buffer gerenciado pelo Kernel e retoma sua execução imediatamente.

Exemplo em C (POSIX Message Queues)

mqueue.h 
#include <mqueue.h>

// Processo Emissor
mqd_t mq = mq_open("/minha_fila", O_WRONLY);
char msg[] = "Dados do Processo A";
mq_send(mq, msg, sizeof(msg), 0); // Envia mensagem

// Processo Receptor
mqd_t mq = mq_open("/minha_fila", O_RDONLY);
char buffer[128];
mq_receive(mq, buffer, sizeof(buffer), NULL); // Bloqueia até ler

Vantagens e Desvantagens

Vantagens
  • Isolamento total de memória (não há risco de corrupção direta de RAM).
  • Funciona perfeitamente em sistemas distribuídos (através de Sockets de Rede).
  • Facilita a modularização e desacoplamento de sistemas.
Desvantagens
  • Overhead de cópia de dados entre espaço do usuário e do kernel.
  • Desempenho inferior comparado à memória compartilhada em grandes volumes.
  • Necessidade de tratamento para buffers cheios ou mensagens perdidas.
Tópico 2.3.9

Barreiras de Sincronização (Barriers)

Ferramenta de sincronização para cálculos paralelos divididos em fases. Nenhum processo/thread pode avançar para a próxima fase de processamento até que **todos** os participantes tenham atingido a linha de barreira.

Aplicação das Barreiras

  • Algoritmos Paralelos em Etapas: Muito usado em simulações físicas, processamento de imagens ou matrizes onde o passo $N+1$ depende dos resultados de *todas* as threads no passo $N$.
  • Evitando Condições de Corrida de Fase: Garante que nenhuma thread adiantada sobrescreva dados que uma thread mais lenta ainda precisa ler da fase anterior.

Exemplo em C (POSIX Barriers)

pthread.h 
#include <pthread.h>

pthread_barrier_t barreira;

// Inicializa a barreira para 4 threads
pthread_barrier_init(&barreira, NULL, 4);

void* worker(void* arg) {
    // Executa Fase 1
    processa_fase_1();

    // Espera todas as threads atingirem este ponto
    pthread_barrier_wait(&barreira);

    // Inicia Fase 2 somente após liberação
    processa_fase_2();
}

Vantagens e Desvantagens

Vantagens
  • Sincronização simples para algoritmos divididos em passos iterativos.
  • Garantia estrita de consistência entre etapas paralelas.
Desvantagens
  • Sensível a "threads lentas" (*Stragglers*): o sistema avança na velocidade da thread mais devagar.
  • Gasto de recursos de CPU enquanto as threads aguardam no ponto de barreira.
Tópico 2.3.10

Evitando Travas: Read-Copy-Update (RCU)

Técnica de sincronização sem travas (*lock-free*) otimizada para cenários com **muitas leituras e poucas escritas** (amplamente utilizada no Kernel do Linux). Leitores acessam os dados sem adquirir travas ou sofrer esperas. O escritor cria uma cópia, modifica-a, troca o ponteiro atomicamente e aguarda o **Grace Period** antes de liberar a versão antiga da memória.

O escritor não bloqueia leitores. Ele aloca uma cópia, modifica, atualiza o ponteiro atomicamente e aguarda o Grace Period para desalocar a versão antiga.

Ocioso

As Três Fases do RCU

  • Leitura Cópia (Publish-Subscribe): O escritor aloca uma nova estrutura na memória, copia o conteúdo existente e faz as alterações desejadas isoladamente.
  • Atualização do Ponteiro (Update): O ponteiro global é redirecionado atomicamente para a nova estrutura. Novos leitores passam a ver os novos dados imediatamente.
  • Grace Period & Liberação (Reclaim): O escritor aguarda até que todas as threads de leitura pré-existentes saiam de suas seções críticas antes de liberar a memória da versão antiga (`kfree`).

Exemplo RCU (Kernel do Linux C)

linux/rcupdate.h 
// --- LEITOR (Sem Locks) ---
rcu_read_lock();
p = rcu_dereference(g_ptr);
if (p) faz_algo_com(p->valor);
rcu_read_unlock();

// --- ESCRITOR ---
struct Dado *novo = kmalloc(sizeof(*novo), GFP_KERNEL);
*novo = *antigo;               // 1. Cópia
novo->valor = 100;             // Modificação
rcu_assign_pointer(g_ptr, novo); // 2. Atualização Atômica
synchronize_rcu();             // 3. Aguarda Grace Period
kfree(antigo);                 // Liberação segura

Vantagens e Desvantagens

Vantagens
  • Leitura com custo quase zero de sincronização (sem contendas de lock ou inválidos de cache).
  • Escalabilidade espetacular em sistemas multiprocessados (SMP).
  • Imune a Deadlocks durante operações de leitura.
Desvantagens
  • Escrita custosa devido à alocação de memória e espera pelo Grace Period.
  • Inadequado para cargas de trabalho com escritas muito frequentes.
  • Maior complexidade na gestão de memória e referências de ponteiros.
